# Keys, Addresses, and Signed Transactions

An educational **Ed25519 toy-chain wallet**. **TEST ONLY — DO NOT USE WITH REAL FUNDS.** Python 3.10+ recommended.

## Files

- `wallet.py` — standalone library: key generation, SHA-256 + Base58Check addresses, canonical transaction encoding, Ed25519 signing and verification.
- `cli.py` — `keygen`, `address`, `sign`, `verify`.
- `tests/test_wallet.py` — security, tampering, canonical serialization and replay tests.
- `generate_deliverables.py` — prints and stores public test vectors, canonical bytes, verification, negative checks and test output.
- `TRANSACTION_FORMAT.md` — exact byte-level specification for independent verification.
- `THREAT_MODEL.md` — key theft, randomness, replay, clipboard, phishing, mainnet safety.
- `deliverables/` — generated public submission examples; **no private keys**.

## Setup

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python generate_deliverables.py
```

## CLI demonstration

```bash
# Public key only by default; the private key is NOT saved
python cli.py keygen --public-out public.json
python cli.py address --public public.json

# Separate TEST-ONLY demo wallet for signing (never submit dev_private.json)
python cli.py keygen --public-out demo_public.json --dev-private-out dev_private.json
python cli.py address --public demo_public.json
```

To create a transaction, copy the `address` from `demo_public.json` into the `sender` field of a JSON file; use another valid toy-chain address as `recipient`. Example format:

```json
{
  "version": 1,
  "network_id": "course-testnet",
  "sender": "REPLACE_WITH_DEMO_PUBLIC_ADDRESS",
  "recipient": "REPLACE_WITH_ANOTHER_VALID_ADDRESS",
  "amount_units": 1250000,
  "nonce": 7,
  "memo_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}
```

The memo hash shown is SHA-256 of the empty string. Replace the address placeholders with actual addresses. Or use the already valid `deliverables/transaction.json` generated by the deliverables script (signed by a **public deterministic test key**, not your new private key).

```bash
python cli.py sign --transaction my_transaction.json --dev-private dev_private.json --output my_signed.json
python cli.py verify --signed my_signed.json --public demo_public.json --nonce-db used_nonces.json --output my_verification.json
# Repeat the same verify command: rejected as replay
```

For instructor verification of the included public test vector (no secret needed):

```bash
python generate_deliverables.py
python cli.py verify --signed deliverables/signed_transaction.json --output deliverables/instructor_verification.json
```

The `--nonce-db` argument enables cross-run replay detection. Omit it for a stateless signature-only check. A state file used by a real verifier must be protected and synchronized; the toy implementation is sequential-use only.

## Acceptance checks

- Different JSON key order or whitespace produces identical canonical bytes.
- Changing version, network, sender, recipient, amount, nonce, or memo hash invalidates verification.
- Incorrect signer, malformed Base58Check address/checksum, invalid signature hex, and repeated nonce are rejected.
- Public signed envelope plus `TRANSACTION_FORMAT.md` is sufficient for independent Ed25519 verification.
- The test-vector seed is deliberately public and **must not be treated as a private key**.

## Submission

Submit the source files, tests, `TRANSACTION_FORMAT.md`, `THREAT_MODEL.md`, and the **public** `deliverables/` directory. Never submit any `dev_private.json` or real private key.
