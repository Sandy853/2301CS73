# Solidity Escrow — specification to local deployment

A one-shot buyer/seller/arbiter ETH escrow. **Read `docs/specification.md` before the contract.**

## Prerequisites
- Python 3.10+
- Foundry (current `forge`, `anvil`, `cast`) from https://getfoundry.sh/
- Internet access for Foundry's initial Solidity compiler download (Solidity 0.8.24)
- No pip packages (`requirements.txt` is intentionally empty)

## One documented command from a clean checkout

```bash
python run_project.py
```

This builds the contract, runs all unit and 256-run fuzz tests, prints test results, starts five-second-ready local Anvil, deploys, funds, disputes, resolves to seller, withdraws, verifies accounting after every transaction, and saves receipts/gas/bytecode. The script stops its Anvil instance afterward. Port 8545 must be free.

If using Windows, run in WSL or a terminal where Foundry executables are on PATH.

## Manual commands

```bash
forge build
forge test -vv
forge test --gas-report
anvil --port 8545
```

In a second terminal, `python run_project.py` requires port 8545 free, so stop the manually started Anvil first.

## Files
- `src/Escrow.sol`: contract with roles, state guards, custom errors, events, pull payments, reentrancy guard.
- `test/Escrow.t.sol`: transition, rejection, event, accounting and fuzz tests (no external test libraries).
- `run_project.py`: Foundry-based Python orchestration and deploy/interact script.
- `docs/specification.md`: requirements and invariants.
- `docs/state_machine.mmd`: Mermaid state diagram (view in Mermaid-compatible Markdown tools).
- `docs/threat_model.md`: threats, mitigations and known liveness limitations.
- `deliverables/`: generated by runner: build.log, test_results.txt, gas_report.txt, transaction_receipts.json, deployment_report.json, deployed_bytecode.hex.

## Accounting and terminal states

`contract.balance == escrowed + totalPending` is asserted after each normal transaction and across tests. Credit is assigned on release/resolution; only the beneficiary can withdraw. Withdrawal does not change the terminal state. External forced ETH may break exact raw-balance equality, as documented in the threat model.

## Important design constraint

The mandated state machine allows `Created -> Cancelled` only. Accordingly mutual cancellation is possible **before funding**, not after funding. Funded escrow can remain locked if no party disputes and the buyer never releases; after dispute, arbiter inactivity can lock funds. Production use requires a revised specification with deadlines or funded cancellation/recovery.

## Local deployment safety

The script uses Anvil's **public test mnemonic**. Never send real assets to these accounts, never use these keys on a public network. No real network deployment is performed.

## Event and gas verification

All receipts contain `status`, `logs`, `gasUsed`, `contractAddress` (on deployment), and transaction hashes. `deployment_report.json` aggregates event topic hashes, gas totals, bytecode size, balances and contract address. `forge test --gas-report` supplies function-level gas measurements. Event names and arguments are verified in Solidity tests via `expectEmit`.
